# 一次全链路博客系统修复：从权限审计到线上发布

![博客系统全链路修复记录](/media/blog_covers/security-audit-20260812.svg)

这次修复的目标，不是把页面“改到能用”为止，而是把一次真实的内容发布链路重新走通：管理员能安全登录，普通访客只能看到应该公开的内容，上传的文件经过校验，前端在移动端不会因为一个按钮或一个弹窗卡住，最后还要在服务器上可验证、可回滚地发布。

## 一、先把问题分成四层

第一层是权限。原本只要拿到一个有效登录态，就可能访问一些管理接口；分类、标签、评论、文件和动态这些资源没有完全统一的角色边界。修复后，系统把“登录”和“内容管理”拆开：普通用户可以拥有自己的登录态，但只有管理员、编辑或审核角色才能进入内容管理接口，用户管理则继续收紧到管理员。

第二层是公开数据。公开评论不应该把邮箱返回给浏览器，动态作者也不应该把后台权限、登录信息或其他管理字段顺手带出去。因此后台为公开接口单独准备了脱敏序列化器，而不是直接复用管理端的完整序列化器。分类和标签增加启用状态，停用项不再出现在公开内容筛选中，但管理端仍能看到并恢复它们。

第三层是内容安全。Markdown、搜索高亮、动态预览和评论都属于“用户输入会重新回到页面”的位置。前端预览使用白名单清洗，搜索高亮同时转义 HTML 和正则特殊字符，避免关键词被当成正则，也避免标题中的标签被直接注入页面。评论接口继续限制长度和字段格式，公开返回不再包含邮箱。

第四层是运行环境。应用不应该用 root 进程承载 Web 请求。线上保留了既定的 root 密码登录要求，但 Django/Gunicorn 已切换为独立的 `blog` 低权限用户，只对媒体目录拥有写权限；环境文件、代码和数据库备份保持更严格的权限。SSH 增加登录失败次数、登录宽限时间、空闲连接回收，并关闭 X11 转发，满足远程维护需求的同时减少暴露面。

## 二、上传链路从“扩展名”升级为“内容校验”

移动端上传最容易暴露兼容性问题。iPhone 常见的 MOV、HEVC、HEIC/HEIF 文件不能只看浏览器传来的 MIME，因为不同浏览器和系统可能给出空值或不同的别名。修复后的校验同时检查文件大小、扩展名、MIME 和文件头：图片检查常见图片签名，PDF 和 Office 文件检查对应魔数，视频检查 MP4/MOV 的 `ftyp` 标记；对于 HEVC 这类可能只有裸流的情况保留兼容路径，但仍限制扩展名、MIME 和大小。

这样做的好处是，用户体验和服务端安全不必二选一。移动端可以选择相册中的实况图片或视频，服务端仍能拒绝明显伪装的文件。已有的视频处理流程继续把适合网页播放的格式交给转码步骤，页面只需要加载更友好的版本；超大文件则在进入存储服务前直接给出可理解的错误提示。

## 三、会话令牌不再把长期凭据放进浏览器存储

这次还统一了两个前端的会话实现：短期 access token 只保存在前端需要读取的地方，长期 refresh token 改为 HttpOnly Cookie，由浏览器自动携带，前端 JavaScript 不再读取或持久化它。access 过期时，客户端通过带凭据的刷新接口获取新的短期 token；退出登录时，服务端同时让 access 和 refresh 失效并清理 Cookie。

这会让登录流程更接近浏览器安全模型：XSS 即使读到了前端存储，也拿不到长期刷新令牌；服务端仍然可以通过黑名单和过期时间控制旧令牌。与此同时，接口返回和前端存储结构已经同步调整，避免旧客户端继续把不存在的 refresh 字段当成本地状态。

## 四、验证不是最后的形式，而是修复的一部分

本次提交前完成了三端回归：后端 88 个测试全部通过，覆盖权限、评论脱敏、分类/标签状态、上传文件头、登录 Cookie 和刷新接口；管理端 277 个测试全部通过，并成功构建；博客前台 28 个测试全部通过，并成功构建。构建产物进入带版本号的发布目录，线上通过软链接原子切换，旧版本仍然保留，出现异常时可以切回。

数据库迁移前先备份应用、环境文件和 MySQL 数据库，再执行迁移和静态文件收集。发布后检查 Django 配置、SSH 配置、Nginx 配置和 systemd 服务状态，并确认 frps 等既有服务没有被误伤。这个顺序看起来比直接上传文件慢一点，但它把“代码改对了”和“线上真的可用”连接了起来。

## 五、这次修复留下的下一步

安全和功能修复完成后，还可以继续做三件事：为登录、刷新、上传和评论接口补充限流与告警；为视频转码增加任务状态和失败重试提示；在前端继续拆分过大的编辑器资源，降低首次加载成本。它们不应该和本次修复混在同一个大改动里，而应该继续用小步提交、可回滚发布和真实链路验证的方式推进。

一次可靠的发布，不只是页面看起来正常，而是权限、数据、文件、会话、构建和运行环境都能解释清楚。把这些步骤记录下来，下一次遇到类似问题时，就不必从“哪里可能坏了”开始猜，而可以从证据和验证结果开始排查。
